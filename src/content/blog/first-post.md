A project becomes much more interesting when other people can use it. This note follows the first move from a local development loop to an automated static deployment: the decisions, the small failures, and the confidence that came from making each step repeatable.

## The useful part of automation

Automation is not about removing people from the process. It is about removing the guesswork from the parts we already understand. A clean build, a predictable artifact, and a deployment that can be repeated on demand create more time for the work that still needs judgment.

The next iteration is already clear: improve the feedback loop, keep the interface calm, and make every change easy to inspect.
